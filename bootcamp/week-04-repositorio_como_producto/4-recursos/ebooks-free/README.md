# 📚 Lecturas gratuitas — Semana 04

Ninguno es un manual de GitLab: son las fuentes de las ideas que la semana aplica. Todas gratuitas y accesibles sin registro.

| Recurso | Qué aporta a esta semana |
|---|---|
| [Documenting Architecture Decisions](https://cognitect.com/blog/2011/11/15/documenting-architecture-decisions) | El artículo de Michael Nygard que inventó el ADR. Dos páginas, quince años después sigue siendo la referencia. Léelo antes de escribir el ADR-001 |
| [Write the Docs — Documentation Guide](https://www.writethedocs.org/guide/) | La guía de la comunidad que más piensa sobre documentación técnica. El capítulo sobre los distintos tipos de lector explica por qué el README y la wiki no son lo mismo |
| [Diátaxis](https://diataxis.fr/) | El marco que separa tutorial, guía práctica, referencia y explicación. Responde la pregunta "¿por qué mi README no funciona?" mejor que cualquier plantilla |
| [The GitLab Handbook](https://handbook.gitlab.com/) | El manual interno de la empresa, público y completo. Es el ejemplo más grande que existe de documentación tratada como producto, con sus aciertos y sus excesos |
| [Choose a License](https://choosealicense.com/) | Corto y decisivo. Es además la fuente de los textos que usa la librería con la que GitLab detecta tu licencia |
| [Pro Git — capítulo 10, Git Internals](https://git-scm.com/book/en/v2/Git-Internals-Git-Objects) | Por qué Git guarda cada versión completa de un binario. Entender el modelo de objetos hace obvio el problema que resuelve LFS |
| [Google — Site Reliability Workbook, "On-Call"](https://sre.google/workbook/on-call/) | Qué tiene que tener un runbook para servir a las tres de la mañana. Es el guion de la página de runbook de la práctica 02 |

> [!TIP]
> Si solo lees una cosa esta semana, que sea el artículo de Nygard. Son dos páginas y cambia la forma de escribir la primera decisión del proyecto, que es la que más se lee.

> Enlaces comprobados en agosto de 2026.
