# 📚 Lecturas gratuitas — Semana 08

Ninguno es un manual de GitLab: son las fuentes de las ideas que la semana aplica. Todas gratuitas y accesibles sin registro.

| Recurso | Qué aporta a esta semana |
|---|---|
| [A successful Git branching model](https://nvie.com/posts/a-successful-git-branching-model/) | El artículo original de Git Flow, con la nota que su autor añadió en 2020 desaconsejándolo para software que se entrega de forma continua. Leer las dos partes juntas enseña más que cualquier comparativa |
| [Trunk Based Development](https://trunkbaseddevelopment.com/) | El modelo explicado por quienes lo defienden, con su sección sobre ramas de release y *cherry-pick* |
| [Keep a Changelog](https://keepachangelog.com/es-ES/1.1.0/) | Por qué un CHANGELOG es para personas y no para máquinas, y de dónde salen las categorías `Added`, `Fixed`, `Changed` que usa GitLab |
| [DORA — Capabilities](https://dora.dev/capabilities/) | Las prácticas que la investigación asocia con mejores métricas: control de versiones, trunk-based, lotes pequeños. Cada una con cómo medirla |
| [Accelerate State of DevOps Report](https://dora.dev/research/) | Los informes anuales, gratuitos con registro opcional. El metodológico explica cómo se definen y se agrupan las métricas |

> [!TIP]
> Si solo lees una cosa esta semana, que sea la nota de 2020 al principio del artículo de Git Flow. Es raro que el autor de un modelo explique por escrito cuándo no usarlo, y es exactamente la pregunta del ADR-006.
